# 直播监控矩阵 Live Grid Monitor · 产品需求文档（PRD v1.0）

> 立项日期：2026-09-02 ｜ 文档版本：v1.0 ｜ 状态：已确认，进入开发

---

## 1. 背景与目标

### 1.1 问题

直播间运营/选品/竞品调研人员需要**同时盯多个竞品直播间**，并回答三类问题：

1. 这个直播间**什么时候开播、播了多久**？
2. 直播间**人气如何变化**（在线人数走势）？
3. 主播**什么时候在放广告/带货**，广告占了多长时间？

现有手段的痛点：

- 逐个打开浏览器标签页 → 标签一多就卡死，且无法并排观察
- 人工记录开播/广告时间 → 靠人盯，误差大、不可持续
- 平台官方后台只看自己的号，**看不到竞品**

### 1.2 产品定位

一个**自部署的多平台直播间九宫格监控台**：低码率多画面预览 + 直播数据自动采集 + 广告时段自动识别 + 数据报表。

### 1.3 目标用户

| 角色 | 场景 | 核心诉求 |
|---|---|---|
| 直播运营 | 每天盯 5–9 个竞品直播间 | 一眼扫完全部画面，异常立刻发现 |
| 选品/投放 | 评估某个品类的带货节奏 | 广告占比、峰值人气、开播时段分布 |
| 电商卖家 | 长期挂机记录竞品 | 数据留存、可导出、可复盘 |

### 1.4 非目标（1.0 明确不做）

- ❌ 不做直播录制落盘（只存数据，不存视频）
- ❌ 不做弹幕完整采集与情感分析
- ❌ 不做多用户/权限/账号体系
- ❌ 不做云端 SaaS 托管（自部署，数据不出本机）
- ❌ 不做移动端适配

## 2. 需求范围

### 2.1 功能需求

#### F1 九宫格监控墙（P0）

| 编号 | 需求 | 验收标准 |
|---|---|---|
| F1.1 | 固定 3×3 共 9 个宫格 | 空宫格显示"添加"引导；点击可添加直播间 |
| F1.2 | 每格独立播放一路直播画面 | 9 路同时播放不崩溃；单格异常不影响其他格 |
| F1.3 | 全链路静音 | 所有 `video` 元素 `muted=true`、`volume=0`；音频分析链路不接 `destination` |
| F1.4 | 最低画质播放 | HLS 锁定 level 0 并禁用 ABR 升档；FLV 由后端挑选最低档 `pull_url` |
| F1.5 | 单格信息角标 | 显示主播/标题、实时在线人数、本场已开播时长、状态（直播中/广告中/未开播/异常） |
| F1.6 | 单格操作 | 重新拉流、强制刷新流地址、人工校正广告、移除、双击放大 |
| F1.7 | 流地址缓存 | 后端 TTL 缓存（默认 30 分钟），避免每格反复请求平台接口 |

#### F2 直播间管理（P0）

| 编号 | 需求 | 验收标准 |
|---|---|---|
| F2.1 | 粘贴分享链接自动识别平台 | 支持抖音/快手/淘宝/京东/视频号/小红书 URL 与 m3u8/flv 直链 |
| F2.2 | 添加前解析预览 | 展示标题、主播、roomId、是否在播 |
| F2.3 | 宫格位置自动分配 / 手动指定 | 占满 9 格时提示"最多 9 个" |
| F2.4 | 平台级 Cookie 配置 | 支持全局环境变量 + 房间级单独覆盖 |

#### F3 数据采集（P0）

| 编号 | 需求 | 验收标准 |
|---|---|---|
| F3.1 | 定时轮询采集（默认 30s） | 采样点写入 `metrics_samples` |
| F3.2 | 开播时长记录 | 自动维护"场次"生命周期，记录 start / end / duration |
| F3.3 | 在线人数记录 | 记录峰值、均值；提供时间曲线 |
| F3.4 | 离线宽限判定 | 连续 3 次判定离线才关场，避免断流把一场切成多段 |
| F3.5 | 手动关场 | 主播下播但采集器未识别时，可手动结算 |

#### F4 广告时段识别（P0 / 1.0 核心差异化）

| 编号 | 需求 | 验收标准 |
|---|---|---|
| F4.1 | 画面/音频自动识别 | 每秒抽帧 + 音频 RMS，滑动窗口（30s）多信号融合打分 |
| F4.2 | 滞回状态机 | 进入广告需连续 8s 超阈值，退出需连续 15s 低于阈值×0.75 |
| F4.3 | 噪声过滤 | 时长 < 5s 的判定自动丢弃 |
| F4.4 | 实时可视化 | 每格底部显示置信度进度条 + 阈值刻度线 |
| F4.5 | 人工校正 | 误报/漏报可一键修正，并自适应微调阈值（±0.03） |
| F4.6 | 降级策略 | 跨域导致画面/音频不可用时，自动降低对应信号权重而非整体失效 |

> 详见 [`AD_DETECTION.md`](./AD_DETECTION.md)

#### F5 数据报表（P0）

| 编号 | 需求 | 验收标准 |
|---|---|---|
| F5.1 | 总览卡片 | 直播间数、累计时长、场次、峰值在线、广告总时长、广告占比 |
| F5.2 | 按房间聚合表 | 场次/时长/峰值/均值/广告段数/广告时长/广告占比 |
| F5.3 | 时间范围切换 | 24 小时 / 7 天 / 30 天 |
| F5.4 | 单房间明细 | 场次列表 + 广告时段列表（含置信度、来源、信号快照） |
| F5.5 | CSV 导出 | 带 UTF-8 BOM，Excel 直接打开不乱码 |

### 2.2 平台支持矩阵（1.0 实际状态）

| 平台 | 画面 | 在线人数 | 稳定性 | 说明 |
|---|---|---|---|---|
| 抖音 | ✅ | ✅ | `stable` | 基于 `webcast/room/web/enter`，社区方案广泛使用 |
| 快手 | ✅ | ✅ | `experimental` | SSR + GraphQL，建议配置 Cookie |
| 淘宝直播 | ⚠️ | ⚠️ | `experimental` | mtop Cookie 通道（`appKey=12574478` 老式签名），需 `_m_h5_tk`；升级 mtgsig 后需抓包直链兜底 |
| 京东直播 | ✅ | ❌ | `experimental` | **2026-09 实测**：`lives.jd.com` + 网关 `getImmediatePlayToM` 匿名出流（含直播状态）；标题/在线人数走推送通道，1.0 未采 |
| 微信视频号 | ❌ | ❌ | `stub` | 无公开 Web 接口 |
| 小红书 | ❌ | ❌ | `stub` | 需 x-s / x-t 动态签名 |
| m3u8 / flv 直链 | ✅ | ❌ | `stable` | 兜底通道，也是联调通道 |

> `experimental` / `stub` 平台解析失败**不阻止添加**：分享链接以占位房间保存并记录原因，
> 可补 Cookie 或「刷新流地址」重试；最坏情况下用浏览器抓包得到 `.m3u8/.flv` 后走直链接入。
> 新增平台接入详见 `ARCHITECTURE.md`。

### 2.3 非功能需求

| 编号 | 需求 | 指标 |
|---|---|---|
| N1 | 并发路数 | 9 路 360p 同时播放，CPU（M 系列 Mac）< 60% |
| N2 | 启动时间 | 冷启动到首帧 < 5s |
| N3 | 数据精度 | 在线人数采样间隔 30s；时长精确到秒 |
| N4 | 可维护性 | 新增平台只需新增一个适配器文件 + 一行注册 |
| N5 | 数据主权 | 全部数据存本地 SQLite，不上传任何第三方 |
| N6 | 容错 | 单路失败不影响其他路；流地址失效自动重试一次 |

## 3. 数据模型

```
rooms (直播间)
  └── live_sessions (场次：一次开播到下播)
        ├── metrics_samples (采样点：在线人数 / 点赞数)
        └── ad_segments     (广告时段：起止 / 时长 / 置信度 / 来源)
```

| 表 | 关键字段 |
|---|---|
| `rooms` | id, platform, share_url, room_id, title, anchor_name, slot, quality, cookie |
| `live_sessions` | id, room_id, start_at, end_at, duration_sec, peak_online, avg_online, ad_count, ad_duration_sec |
| `metrics_samples` | room_id, session_id, ts, online_count, like_count, is_live |
| `ad_segments` | room_id, session_id, start_at, end_at, duration_sec, confidence, signals, source(auto/manual), verified |
| `stream_cache` | room_id, stream_url, format, quality, expires_at |

## 5. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 平台接口变更导致解析失效 | 高 | 适配器隔离 + 明确的错误提示 + 直链兜底 |
| 风控封禁 IP | 中 | 轮询间隔默认 30s 且可配置；支持 Cookie |
| 广告识别准确率不达预期 | 中 | 多信号融合 + 阈值可调 + 人工校正闭环 |
| 9 路并发播放性能 | 中 | 最低画质 + 静音 + 离屏暂停策略 |
| 跨域导致画面/音频信号不可用 | 低 | 自动降级，权重重分配 |

## 6. 验收标准（v1.0）

1. 空宫格点击 → 粘贴抖音直播间链接 → 解析出标题主播 → 添加后画面正常播放且无声
2. 连续运行 1 小时，9 路画面不中断
3. 报表页能看到该时段的场次、峰值在线、广告段；导出的 CSV 用 Excel 打开中文正常
4. `cd server && npm test` 冒烟测试 30 项全通过
