# 广告时段自动识别设计说明（v1.0）

## 1. 问题定义

平台接口**不会**告诉你"主播开始放广告了"。因此只能从画面与音频特征反推。
本项目的做法是把这个问题建模为**二分类时序分割**：

```
输入：每路直播每秒一个多模态特征向量
输出：LIVE / AD 的连续状态序列（带滞回，避免抖动）
```

## 2. 为什么放在浏览器端

9 路视频如果回传服务端做抽帧，意味着：

- 每路上行 ~100KB/s → 9 路 ≈ 900KB/s 持续带宽
- 服务端需要 9 路解码，成本高

而浏览器端每路只需**每秒 1 帧 9×8 像素**的差分计算，开销可忽略。
因此：**识别在前端，落库在后端**。后端只接收结构化结果。

## 3. 特征信号

| 信号 | 计算方式 | 判别依据 | 权重 |
|---|---|---|---|
| `repeatRatio` | 30s 窗口内出现 ≥2 次的 dHash 占比 | 循环播放同一段口播/混剪素材是最强广告特征 | 0.32 |
| `sceneChangeRate` | 相邻帧 dHash 汉明距离 ≥12 的比例 | 广告混剪剪辑碎；真人讲解切换平缓 | 0.28 |
| `audioStability` | RMS 变异系数 `cv` 的反向指标 `(1.1-cv)/0.9` | 录播素材能量平稳；真人讲解起伏大 | 0.20 |
| `keywordScore` | 弹幕/标题关键词命中，随时间线性衰减 | "上车/小黄车/优惠券/拍下" 等 | 0.20 |

### 感知哈希（dHash）

```
1. 把视频帧画到 9×8 的 canvas（宽多 1 像素用于横向差分）
2. 转灰度：0.299R + 0.587G + 0.114B
3. 逐行比较相邻像素，右 < 左 记 1，否则记 0
4. 得到 64 bit 指纹
```

帧间差异用**汉明距离**衡量：

- `< 6`：几乎同一画面
- `6–12`：镜头内运动
- `≥ 12`：发生了场景切换

## 4. 融合打分

```js
score = 0.32 × clamp(repeatRatio)
      + 0.28 × norm(sceneChangeRate, 0.2, 0.75)
      + 0.20 × audioStability
      + 0.20 × clamp(keywordScore)
```

**权重重分配**：若跨域导致音频不可用，`audioStability` 恒为 0 会把总分系统性压低 20%，
此时按比例把音频权重摊回其余信号，保证阈值语义在不同环境下一致。

**兜底规则**：`sceneChangeRate < 0.02 && repeatRatio > 0.95` → 判定为**黑屏/卡死**而非广告，分数打 3 折。

## 5. 状态机（滞回）

```
        score ≥ T 连续 8s
  LIVE ─────────────────────▶ AD
       ◀─────────────────────
        score < 0.75T 连续 15s
```

进入阈值 `T` 与退出阈值 `0.75T` 分离，形成滞回带，防止分数在阈值附近来回抖动导致广告段碎片化。

默认 `T = 0.62`，前端滑块可在 `0.35 ~ 0.90` 实时调整。

## 6. 人工校正闭环

```
用户在某个格子点「📢 标为广告」
  → 后端写入 source='manual', verified=1 的段
  → 前端调用 markManual('false_negative')，阈值 -0.03

用户点「🚫 判定为讲解」
  → 后端把覆盖区间内的自动段标 verified=1（保留数据供回溯）
  → 前端调用 markManual('false_positive')，阈值 +0.03
```

阈值自适应范围钳制在 `[0.35, 0.90]`。

## 7. 已知局限与改进方向

| 局限 | 表现 | 后续改进 |
|---|---|---|
| 全程背景音乐 | `audioStability` 虚高 → 误判为广告 | 引入频谱平坦度区分音乐/人声 |
| 真人讲解商品（无循环素材） | `repeatRatio` 低 → 漏判 | v1.1 接入弹幕关键词，强化 `keywordScore` |
| 单路多机位切换 | `sceneChangeRate` 干扰 | 用短窗口方差过滤 |
| 静态商品展示（不讲话） | 可能误判 | 结合"画面静止 + 无音频活动"单独归类为 `IDLE` 状态 |

**v1.1 计划**：把启发式打分升级为可训练模型——用人工校正数据积累标注集，
在后端训练一个轻量 GBDT/逻辑回归，前端仍只做特征提取。
